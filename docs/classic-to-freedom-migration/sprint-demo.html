Workflow 1

Як складний Classic-код перетворюється на зрозумілу поведінку

classic-behaviour-analysis.workflow.jsЗапускається лише тоді, коли є що пояснювати
01 · CONTEXT

Зібрати карту

Знаходить усі сторінки та спільні частини логіки, щоб нічого не загубити.

02 · DESCRIBE

Пояснити

Кілька агентів паралельно описують поведінку окремих сторінок через classic-ui-expert.

03 · CRITIQUE

Знайти прогалини

Окремий агент шукає рядки без пояснення та суперечливі описи.

04 · MERGE

Зібрати результат

Об'єднує картки поведінки та індекс, який повертається в план.

04 · Context → Describe → Critique → MergeПовнота рахується, а не декларується
Що сказати: Уявіть групову роботу студентів: спочатку викладач ділить тему, потім групи описують свої частини, рецензент знаходить пропуски, а редактор збирає один узгоджений документ.
Skill 2

classic-ui-expert — перекладач із коду на бізнес-поведінку

ФАЗИ 1–2

Знайти все

Визначає всі сторінки та читає повний ланцюжок їхніх Classic-розширень.

ФАЗИ 3–5

Зрозуміти

Перелічує кожен елемент коду, групує їх у поведінку та знаходить зовнішні залежності.

ФАЗА 6

Описати

Створює картки: коли поведінка запускається, що робить, навіщо потрібна і як її перевірити.

Важливо: цей skill не запускає окремий workflow. Його викликають агенти всередині workflow аналізу.
05 · Код → зрозуміла поведінкаЯкщо доказу немає — чесно фіксує невідоме
Що сказати: Classic UI Expert — як аналітик, який читає програму й пише інструкцію для майбутнього розробника. Він не вигадує відповідь: невідому поведінку фіксує як прогалину з поясненням, що треба перевірити.

Що сказати: Це як виробнича лінія з незалежним контролем. Той, хто зібрав деталь, не ставить собі оцінку. Інший перевіряє факт, третій — чи достатній доказ. Невдалий результат повертається на ремонт.
