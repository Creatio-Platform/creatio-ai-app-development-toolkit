# Agent 04 — Implementation Orchestrator

## Role

Read `plan.md`, generate all package files via skills and templates, and validate output.

## Input/Output

- Input: `output/<AppName>/plan.md`, `output/<AppName>/workflow-state.json`
- Output: `output/<AppName>/packages/<PkgName>/`

## Context

Read:
- `context/essentials.md`
- `context/schema-reference.md`
- `context/ui-reference.md`
- `context/data-bindings-reference.md`
- `context/bindings-lookup.json`

Use templates from `templates/` as structural reference.

## Skills

- `skills/package-descriptor-creation/SKILL.md`
- `skills/entity-creation/SKILL.md`
- `skills/page-creation/SKILL.md`
- `skills/data-bindings-creation/SKILL.md`

Addon generation has no separate skill file. Generate addon schemas using `templates/addons/`.

## Steps

### 0. Check Gate R (mandatory)

```bash
scripts/check-approval-gate.sh <AppName>
```

If this fails, stop immediately.

### 1. Parse plan

Extract package identity, entities, pages, addons, bindings, and seed data.

### 2. Create package skeleton

```bash
mkdir -p output/<AppName>/packages
cd output/<AppName>/packages
clio new-pkg <PkgName>
```

Package path must be `output/<AppName>/packages/<PkgName>/`.

### 3. Generate package descriptor

Use `skills/package-descriptor-creation/SKILL.md` to create/update:
- `output/<AppName>/packages/<PkgName>/descriptor.json`

Required defaults:
- `PackageVersion`: `1.0.0`
- `Maintainer`: `Customer`
- `DependsOn`: `[]`

### 4. Clean skeleton

Remove unnecessary scaffold files/directories generated by `clio new-pkg`:
- `*.csproj`, `*.sln`, `packages.config`
- `Files/`, `Properties/`, `Resources/`, `SqlScripts/`, `Assemblies/`
- `placeholder.txt`

Keep:
- package `descriptor.json`
- `Schemas/`
- `Data/`

### 5. Group 1 — Entities via MCP (parallel)

Use `skills/entity-creation/SKILL.md` for each entity from plan:
- Lookup entities via `entity.create_lookup`
- Main entities via `entity.create`

Required outputs per entity:
- `Schemas/<EntityName>/descriptor.json`
- `Schemas/<EntityName>/metadata.json`
- `Schemas/<EntityName>/properties.json`

Persist MCP evidence:
- Raw response: `output/<AppName>/mcp-logs/<EntityName>.json`
- Summary: `output/<AppName>/mcp-entity-report.md`

Retry MCP call up to 3 times (10s delay). If still failing, stop and report blocker.

### 6. Group 2 — Pages (parallel)

Use `skills/page-creation/SKILL.md` for each page from plan.

Required outputs per page:
- `Schemas/<PageName>/descriptor.json`
- `Schemas/<PageName>/metadata.json`
- `Schemas/<PageName>/properties.json`
- `Schemas/<PageName>/<PageName>.js`

### 7. Group 3 — Addons + Data Bindings (parallel)

Addon generation (template-based):
- Use `templates/addons/*` to create for each addon:
  - `Schemas/<AddonName>/descriptor.json`
  - `Schemas/<AddonName>/metadata.json`
  - `Schemas/<AddonName>/properties.json`

Data bindings:
- Use `skills/data-bindings-creation/SKILL.md` to create:
  - `Data/SysModuleEntity_<Entity>/descriptor.json|data.json|filter.json`
  - `Data/SysModule_<Entity>/descriptor.json|data.json|filter.json`
  - `Data/<LookupEntity>_Lookup/descriptor.json|data.json|filter.json`

### 8. Validate generated package

File structure:
- package root descriptor exists
- every entity/page/addon/binding from plan has expected files
- MCP evidence files exist

Cross-reference checks:
- entity UIds in pages/addons/bindings match plan
- `SysModule.SysModuleEntity` equals `SysModuleEntity.Id`
- `CardSchemaUId`/`SectionSchemaUId` match form/list page UIds from plan

Format checks:
- all `.json` files parse successfully
- all page `.js` files have valid syntax

GUID checks:
- no duplicate GUIDs across generated files
- generated GUIDs match plan values

## Completion Criteria

- Gate R passed
- All package files generated with correct structure
- Cross-references validated
- JSON/JS validity confirmed
- No GUID collisions
- MCP evidence persisted
- Package ready for `clio push-pkg`
